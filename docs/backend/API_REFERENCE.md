# API Reference — Conventions

No endpoint exists yet. This file fixes the **conventions** every endpoint follows. The endpoint catalogue is in `brain/API_CONTRACTS.md`; request/response shapes in `docs/integration/DATA_CONTRACTS.md`. Items marked *Proposed* are ratified through DECISIONS.

## REST conventions

- Base path `/api/v1` (Proposed, ADR-010). JSON, UTF-8, `snake_case` field names on the wire.
- Nouns for resources, plural (`/documents`). Actions that are not CRUD use a sub-resource noun (`/documents/{id}/analysis`).
- Methods: `GET` safe/idempotent, `POST` create/run, `PATCH` partial update, `DELETE` remove. `PUT` only for full replacement.
- Status codes: 200 OK, 201 Created (with `Location`), 202 Accepted (async work), 204 No Content, then the error codes in API_CONTRACTS.
- IDs: opaque UUID strings. Timestamps: ISO 8601 UTC with `Z`.
- Every response carries `X-Request-ID` (echoed or generated); it also appears in error bodies.

## Authentication (Planned)

- `Authorization: Bearer <access_token>` (JWT, `HS256` per settings, 15 min TTL).
- Refresh via a refresh token (14 d), rotated on use, stored hashed; delivered as an httpOnly, Secure, SameSite cookie or in the body — decide in an ADR before building.
- 401 `unauthorized` for missing/invalid token; 403 `forbidden` for valid token without permission; use 404 instead of 403 when revealing existence would leak data.
- Whether anonymous use of the assistant is allowed is undecided.

## Pagination

Cursor-based (Proposed) for lists that can grow (messages, documents): request `?limit=` (default 20, max 100) and `?cursor=`; response `{ "items": [...], "next_cursor": "string|null" }`. Small fixed lists (categories, jurisdictions) may return a plain array wrapped as `{ "items": [...] }`.

## Errors

Only the envelope in API_CONTRACTS. Validation errors use `validation_error` with `details` as a list of `{ "field": "path.to.field", "message": "..." }`. Messages are user-safe.

## Versioning

- Breaking changes require a new path version or a new field name with a deprecation period. Additive, optional fields are non-breaking.
- Deprecations announced in this file and in response headers (`Deprecation`, `Sunset`) before removal.
- OpenAPI is generated by FastAPI; the generated schema must match `DATA_CONTRACTS.md`. Provide `response_model` and declared error responses on every route.

## Streaming

Server-Sent Events for long answers (Proposed): `Content-Type: text/event-stream`; event names and payloads in DATA_CONTRACTS. Errors mid-stream are sent as an `error` event with the standard envelope, then the stream closes.

## Uploads

`multipart/form-data`, one file per request, limits from `MAX_UPLOAD_BYTES`. Shape in DATA_CONTRACTS. Return 202 and a processing status resource when parsing is asynchronous.

## Rate limiting

`RATE_LIMIT_PER_MINUTE` per user (or IP when anonymous). On exceed: 429 `rate_limited` with `Retry-After`. Expensive routes (answers, analysis) get tighter limits.

## Documenting an endpoint

For each endpoint record: method + path, auth, request schema, response schema, error codes, idempotency, rate-limit class, and an example. Keep examples free of real legal citations unless they come from a registered source.
